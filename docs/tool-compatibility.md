# Tool compatibility

The `skills/` folders follow the [Agent Skills](https://agentskills.io/specification) standard and work in any client that implements it. Beyond that, two integration layers ship here: a Claude Code plugin (`.claude-plugin/`, `agents/`, `commands/`, `.mcp.json`, `hooks/`, `monitors/`, `workflows/`) and an OpenCode plugin (`opencode/`, installed by `scripts/install-opencode.sh` — see [opencode-setup.md](opencode-setup.md)). Other tools ignore both.

| Capability | Claude Code | OpenAI Codex | OpenCode | pi |
|---|---|---|---|---|

## Notes per tool

- **Claude Code**: full feature set. Agents are namespaced `dotnet-episteme-skills:review:<name>`; Synopsis MCP tools appear as `mcp__plugin_dotnet-episteme-skills_synopsis__<tool>`. MCP servers are not auto-respawned after a crash — reconnect with `/mcp`.
- **OpenAI Codex**: this repo installs as a Codex plugin **without any Codex-specific files** — verified on codex-cli 0.145.0: `codex plugin marketplace add <repo-or-owner/repo>` accepts `.claude-plugin/marketplace.json`, `codex plugin add dotnet-episteme-skills@dotnet-episteme-marketplace` caches the bundle under `~/.codex/plugins/cache/`, and all 10 skills then appear in the model-visible prompt (`codex debug prompt-input`). Codex also reads the plugin's `.mcp.json` (`codex mcp list` shows `synopsis`, enabled) and its own hook format is structurally the same as `hooks/hooks.json` (`PreToolUse` + `matcher` + command handlers, blocking via exit 2 with stderr or `permissionDecision: deny`).
  Two known gaps before the review pipeline works there: (1) `${CLAUDE_PLUGIN_ROOT}` is stored **unexpanded** in the MCP command, so the Synopsis launcher needs a form that resolves at spawn time — the CLI does know the names `PLUGIN_ROOT`/`CLAUDE_PLUGIN_ROOT`/`PLUGIN_DATA`/`CLAUDE_PLUGIN_DATA`, so an env-var-based launcher is the likely fix, still to be verified against a logged-in session; (2) `PreToolUse` payloads carry `session_id`/`turn_id`/`tool_name`/`tool_input` but **not** `agent_type` (only `SubagentStart`/`SubagentStop` do), so `git-readonly-guard.sh` cannot scope itself to review agents on Codex without correlating state across events. Subagents are configured under `[agents]` in `config.toml` (`agents.<name>.config_file`, `agents.<name>.description`, `agents.default_subagent_model`, `agents.default_subagent_reasoning_effort`, `agents.max_concurrent_threads_per_session`), and plugins cannot ship them, so mirroring the five reviewer lanes needs config-layer files rather than a plugin component.
- **OpenCode**: full review pipeline via `opencode/dotnet-episteme.js`, whose `config` hook registers the skills path, six `review-*` subagents (prompts read from `agents/review/`, so those files stay single-sourced), the `/dotnet-review` command, and the Synopsis MCP server. Skill folders are also consumed unconverted from its native dirs, `.claude/skills`, and `.agents/skills`. Two sharp edges: **never** copy `agents/review/*.md` into an OpenCode agent directory — a comma-string `tools:` key fails the config decode and takes down config resolution for the whole session; and hand-editing `opencode.json(c)` risks the v1/v2 key-mixing trap, where one v2-shaped key in a v1 document silently discards the entire file. Details and verification commands: [opencode-setup.md](opencode-setup.md).
- **pi (badlogic/pi-mono)**: point pi's skills setting at the `skills/` directory. No subagent/delegation primitive; single-context path only.

## The rule for contributors

Never add Claude-only frontmatter keys to any `skills/**/SKILL.md`. Claude-specific behavior belongs in `agents/`, `commands/`, `.mcp.json`, `monitors/`, or `bin/`; OpenCode-specific behavior belongs in `opencode/`.

Corollary for the review pipeline: `agents/review/*.md` stay Claude-shaped and the OpenCode plugin converts them at load time. Keep their frontmatter to `name`, `description`, and a tool restriction — and prefer `tools:` there, since it is a stricter allowlist than `disallowedTools:`. Do not try to make those files serve both tools directly: `tools:` is fatal to an OpenCode config document, and the dual-compatible alternative would force every reviewer down to a denylist.
